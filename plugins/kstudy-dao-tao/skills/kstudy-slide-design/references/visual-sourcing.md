# Kstudy Slide Visual Sourcing

Use this reference before selecting imagery, diagrams, charts, screenshots, public photos, Canva assets, or generated visuals for Kstudy slide decks.

Visuals are not decoration. Every visual must help learners understand, compare, remember, evaluate, or act.

Use this decision rule:

- Real Kstudy photos are for proof.
- Diagrams are for thinking.
- Screenshots are for doing.
- Charts are for evidence.
- Public photos are for social, professional, market, or industry context.
- Generated or Canva visuals are for concept illustration, not proof.
- Napkin AI diagrams are for fast concept structure, then brand normalization and slide QA.

## Visual Completeness Gate

Before building the final deck, every slide in the visual plan must have one resolved visual job and one resolved source.

Do not finalize slides with `TBD`, `missing image`, `placeholder`, `stock later`, or unresolved asset paths. Resolve the gap by calling the appropriate connector/tool, asking for the exact missing proof asset, or changing the slide into a self-created diagram, chart, workflow, timeline, matrix, screenshot mockup, icon system, or intentional key visual.

Use local assets first, but do not let "local-first" produce a visually thin deck. Local-first means start local, then escalate when the visual plan requires a stronger or more accurate source.

## Conditional Connector Rules

| Visual need | First choice | Escalate to connector/tool when | Notes |
|---|---|---|---|
| Kstudy proof image: class, learner, mentor, workshop, event, team | Local `assets/photos/` | Local manifest has no suitable image | Use Google Drive connector or Kstudy Drive links. Do not substitute stock/generated people. |
| Real Kstudy class/session/assignment/student example | Local brief/user-supplied material | The slide needs real operational data or examples | Use Kstudy AI Mentor/Supabase only for task-relevant data. Do not invent names, outcomes, scores, or class facts. |
| Public/current context: platform UI, market example, workplace/social context, official tool screenshot | Existing local/public asset notes | The visual must reflect current public information or a real external example | Use web search and original source pages. Keep source URL and rights note. |
| Canva visual, stock/background exploration, fast composition, social derivative | Local HTML/CSS visual or existing image | The deck needs Canva-native assets or a Canva-composed illustration | Use Canva connector for assets/composition. Do not use Canva import as canonical if it breaks layout. |
| Concept key visual: AI, automation, future of work, learning journey | Self-created HTML/CSS key visual | A custom conceptual image would clarify the message better | Use image generation. Mark it as `Generated concept visual, not Kstudy proof`. |
| Concept map, hierarchy, causal chain, 3-6 branch framework, compact process | Self-created HTML diagram | Napkin AI can express the structure faster without reducing accuracy | Use Napkin AI, then follow `references/napkin-ai.md`; keep output transparent and normalize to Kstudy design-system colors. |
| Abstract structure, thinking model, process, comparison, exercise flow | Self-created diagram/chart/workflow | No external proof or photo is needed | Build in HTML. This is a valid resolved visual source. |

If a connector is unavailable, continue only when the slide can be converted to a clear self-created visual. If the claim needs real proof and no proof source is available, ask for the exact missing asset instead of using a weaker substitute.

## Slide Visual Decision Rules

| Slide message | Preferred visual | Notes |
|---|---|---|
| Classroom, workshop, instructor, student outcome | Real Kstudy photo | Use local manifest first. |
| Testimonial, alumni, learner story | Approved real photo + quote card | Do not invent names, claims, scores, or outcomes. |
| Professional, social, market, or workplace context | Public photo or public screenshot with source | Use only when it clarifies context; do not imply Kstudy proof. |
| Specialist concept, mental model, or knowledge structure | Diagram, layered model, concept map, or simple metaphor visual | Use visuals to explain the idea, not to fill space. |
| Workflow, automation, funnel, SOP | Diagram or flowchart | Better than a generic tech photo. |
| Data, KPI, benchmark, timeline | Chart, metric card, timeline | Only visualize supplied or sourced numbers. |
| Strategy, comparison, decision | Matrix, quadrant, comparison table | Highlight one recommendation. |
| Tool lesson or software walkthrough | Screenshot/mockup with annotations | Keep UI current; do not fake real states. |
| Abstract AI/automation concept | Generated illustration or restrained stock image | Avoid robots, glowing brains, handshakes, and generic tech wallpaper. |
| Cover or section divider | Real photo, gradient brand field, or simple key visual | One strong focal point; keep title readable. |

## AI-Generated Visual Rules

Use AI-generated visuals only when they explain or frame a concept better than real photos, diagrams, charts, or screenshots.

Good uses:

- Abstract AI, automation, future-of-work, learning journey, data flow, or agent-workflow concepts.
- Cover or section-divider key visuals that need a strong conceptual scene.
- Metaphor visuals where the audience should feel a professional Vietnamese/Asian context, not a real Kstudy proof moment.

Prompt defaults:

- Prefer Asian/Vietnamese-looking characters when people are included.
- Use modern, practical, premium education style.
- Use Kstudy brand cues: navy, bright blue, cyan, and restrained yellow accent.
- Leave clear safe space for headline or slide content when needed.
- Avoid robots, glowing brains, fake classrooms, fake testimonials, fake Kstudy students, unreadable UI text, exaggerated sci-fi, and generic handshakes.

Always mark these in the visual plan as `Generated concept visual, not Kstudy proof`.

## Cognitive Visual Rules

Choose the visual by the learning job:

| Learning job | Use | Avoid |
|---|---|---|
| Explain an abstract concept | Diagram, layered model, analogy visual | Generic people-in-meeting photos |
| Show cause and effect | Flow, causal chain, before/after map | Decorative tech imagery |
| Compare options or methods | Two-column comparison, matrix, quadrant | Photos that do not encode the difference |
| Show market or social context | Public photo, public screenshot, sourced quote/stat visual | Unsourced claims or dramatic stock photos |
| Teach software or a tool | Real screenshot with annotation | Fake dashboards or outdated UI |
| Prove Kstudy learning experience | Real Kstudy class, mentor, student, or event photo | Stock, generated, or public classroom photos |

Before choosing an image, ask:

1. Does this slide need explanation, proof, context, evidence, or action?
2. Is there authentic or sourced material for the claim?
3. Does a photo explain the message better than a diagram, chart, table, or screenshot?

If the answer to the third question is no, use a diagram, chart, table, timeline, matrix, or screenshot instead of a photo.

## Required Visual Plan

For decks with more than 3 visual slides, create a short internal plan:

| Slide | Message | Visual type | Source | Asset/file | Connector/tool | Crop/layout | Rights/notes |
|---|---|---|---|---|---|---|---|

Use this plan to avoid repeated imagery and to match every visual to the slide's claim.

`Connector/tool` must be one of: `Local`, `Google Drive`, `Kstudy AI Mentor/Supabase`, `Web search`, `Canva`, `Image generation`, `Napkin AI`, or `Self-created HTML`.

## Public Image Sourcing Workflow

Use public images only when the slide needs external context, such as social behavior, workplace scenes, public platform UI, market/industry examples, news context, or official tool screenshots.

Workflow:

1. Define the visual's job: context, evidence, example, or tool walkthrough.
2. Search for a public source with clear rights. Use image search only to discover candidates, then open the original page.
3. Prefer Wikimedia Commons, public-domain collections, Creative Commons-compatible assets, Unsplash, Pexels, Pixabay, official press/media kits, official docs, and public platform screenshots.
4. Check usage rights or license notes. If rights are unclear, do not use the image for public/commercial decks without user approval.
5. Download or copy the selected asset into the project/deck folder, usually `assets/images/public/`.
6. Rename public assets clearly:
   `public-[topic]-[context]-[orientation]-[source-or-license].jpg`
7. Record the source URL and rights note in the visual plan or project notes.

Public images must never be presented as Kstudy classes, Kstudy learners, Kstudy mentors, testimonials, outcomes, or events.

## Kstudy Proof Image Workflow

Use real Kstudy images when the slide claims or implies Kstudy proof: classes, learners, instructors, mentor support, workshops, community, team, testimonials, or training outcomes.

Workflow:

1. Read `assets/photos/manifest.md`.
2. Select from local Kstudy photos first.
3. If local assets are insufficient, search the Kstudy Drive/Sheet asset index.
4. If Drive access is unavailable or the required proof image is missing, ask the user for the exact needed image rather than substituting stock or generated visuals.
5. Copy approved assets into the project/deck folder, usually `assets/images/kstudy/`.
6. Rename Kstudy assets clearly:
   `kstudy-[category]-[context]-[orientation]-[short-description]-[yyyy-mm-dd-or-source].jpg`
7. Record the source in the visual plan.

Proof claims must be supported by authentic material. Do not invent names, numbers, testimonials, outcomes, cohort details, or credentials.

## Slide Implementation Notes

- Use full-bleed photos only with `.scrim-head` and `.scrim-foot`.
- Keep text inside the safe area; photos may bleed, but information may not.
- Crop people respectfully and avoid cutting faces/hands awkwardly.
- Cool-grade photos lightly to match navy/blue; keep skin tones natural.
- Use diagrams/charts when they explain the concept more clearly than photography.
- Do not publish uncertain-rights internet images without user approval.
- For public or external images, keep the source URL in project notes or the visual plan even when the source is not displayed on the slide.
- Use icons sparingly. If an icon does not encode meaning, remove it.
