3. If a Google Drive connector or authenticated browser is available, copy selected photos into a reusable folder named `Kstudy Brand Photo Library`, then rename files with this pattern:
   `kstudy-[category]-[context]-[orientation]-[short-description]-[yyyy-mm-dd-or-source].jpg`
4. If Drive access is not available, cite the source folder URL in the deliverable notes and ask for the needed photos only when the local set cannot satisfy the brief.
5. Use internet images only for non-Kstudy context: market examples, public screenshots, platform UI, industry references, or public event references. Keep source URLs.
6. Use AI-generated images only for conceptual illustrations, abstract hero backgrounds, or future-state scenarios. Do not present generated people, classrooms, testimonials, events, or certificates as real Kstudy evidence.
7. Use Canva search or creation when the active tools expose Canva. Prefer Canva for composited marketing visuals, social/ads layouts, and fast stock/background exploration; still keep Kstudy real photos as the proof layer.

## Visual Decision Rules

Choose the visual format from the content, not from decoration needs:

| Content type | Preferred visual | Notes |
|---|---|---|
| Class, workshop, instructor, learner outcome | Real Kstudy photo | Use local manifest first; crop people respectfully; avoid fake classroom AI images. |
| Testimonial, alumni, student result | Real student photo, quote card, screenshot with permission | Do not invent names, quotes, scores, or employer outcomes. |
| Process, SOP, automation, funnel, workflow | Diagram, flowchart, swimlane, system map | Prefer clean diagrams over unrelated tech photos. |
| Data, KPI, benchmark, timeline | Chart, table, timeline, metric card | Only chart supplied or sourced numbers; mark placeholders clearly. |
| Strategy, positioning, decision | Matrix, quadrant, before/after comparison | Keep one key decision per slide/section. |
| Software/tool lesson | Screenshot, UI mock, annotated workflow | Use current screenshots when possible; do not fake product states as real. |
| Abstract AI/automation concept | Generated illustration or light stock image | Keep it brand-colored; avoid robots, glowing brains, handshakes, and generic tech wallpaper. |
| Landing-page hero | Real Kstudy photo when proof-led; generated/stock only when concept-led | Hero image must communicate the actual offer or audience, not atmosphere only. |

## Required Visual Plan

Before building a deck or landing page with more than 3 visual sections, make a short visual plan:

| Slide/section | Message | Visual type | Source | Asset/file | Crop/layout |
|---|---|---|---|---|---|

Keep this plan internal unless the user asks for it. Use it to avoid repeated generic photos and to match each visual to the slide's actual claim.

## Brand Treatment

- Prefer real people, laptop work, classroom discussion, instructor teaching, workshops, portfolio output, and business training scenes.
- Grade photos slightly cool/navy-blue if needed; keep skin tones natural.
- Use full-bleed photos only with head/foot scrims on slides.
- Use diagrams and charts when they explain better than a photo.
- Keep one strong visual idea per slide or first-viewport section.
- Do not use decorative visuals that compete with the message.

## Citation And Rights

- For Kstudy-owned local assets, no public citation is needed in the artifact unless requested.
- For Google Drive photos, preserve the Drive folder or file URL in project notes when possible.
- For internet images, include source URL and ensure usage is appropriate for the deliverable.
- Do not publish or send external-facing materials using uncertain-rights photos without approval.
