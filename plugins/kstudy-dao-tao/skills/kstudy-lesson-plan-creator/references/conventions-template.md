# Template conventions.md (lưu ở gốc thư mục môn)

Tạo SAU khi bộ 4 file buổi pilot được user duyệt; user xác nhận nội dung trước khi lưu. Đọc lại ĐẦU MỌI lần soạn buổi bất kỳ. Muốn làm khác một mục đã ghi → hỏi user, đồng ý thì sửa file này + thêm dòng Changelog, rồi mới áp dụng.

```markdown
# Conventions học liệu — <Tên môn> (<CODE>)

Chốt sau pilot Buổi <N>, ngày <YYYY-MM-DD>. Mọi buổi phải tuân thủ; muốn khác → hỏi user + cập nhật file này.

## 1. Giọng văn & wording
- Giọng: <vd: giảng dạy gần gũi, xưng "anh/em", câu ngắn>
- Từ dùng / từ tránh ngoài chuẩn chung: <vd: dùng "trí tuệ nhân tạo" lần đầu mỗi tài liệu, sau đó cho phép "AI">
- Mức dùng tiếng Anh: <quy ước cụ thể user đã chốt>

## 2. Slide
- Số slide/buổi: ~<N> · Mỗi phần mở đầu bằng: <quy ước> · Slide kết: <quy ước>
- Giới hạn title: slide thường ≤48 ký tự/9 từ; cover/section ≤60 ký tự/11 từ; bullet ≤14 từ
- Mỗi slide phải có: Mục tiêu học · Thông điệp chính · Visual job · Minh họa · Gợi ý KSD
- Phong cách hình ảnh chung (chuỗi nối vào câu lệnh tạo ảnh): "<chuỗi>"
- Tỷ lệ loại minh họa: <vd: demo phần mềm luôn dùng ảnh chụp màn hình thật>

## 3. Video
- Số video/bài: <3–6, số user thích> · Độ dài ưa dùng: <phút> · Tỷ lệ Cốt lõi/Mở rộng: <~60/40>
- Định dạng ưa dùng theo loại nội dung: <vd: thao tác phần mềm → quay màn hình; khái niệm → slide + đồ họa>

## 4. Demo & thực hành trên lớp
- Cấu trúc demo: <vd: mỗi demo ≤6 bước, luôn kèm 1 mistake>
- Format bài tập lớp: <vd: nhãn "Thực hành N", luôn nêu sản phẩm nộp + tiêu chí đạt dạng checklist>

## 5. Quyết định từ feedback pilot
- <YYYY-MM-DD> <góp ý của user đã tiếp thu — ghi nguyên văn ngắn gọn>

## Changelog
- <YYYY-MM-DD> v1 — chốt sau pilot Buổi <N>.
```
